Selected work / Three perspectives

01

Client & Industry Research

Output — client pitch decks, client preparation

Before a company is discussed with a client or a team, someone has to build its background: how it discloses, who it supplies, how it is governed, who decides, what has just happened to it.

I helped test and document a structured version of that research — nine defined fields per company, run across 14 companies in 8 markets — to find out what is realistically verifiable before relying on it for client work.

The supporting grid records what could be verified. Sources are not equally trustworthy, so each result records how it was obtained; and where something could not be verified, that is recorded too, rather than filled in with something plausible.

Supporting evidence

How I Made Large-scale Research More Reliable

Three problems behind the work in 02. Each one changed how results get checked — not just this project's results.

01 — Inconsistent source formats

Report PDFs are formatted inconsistently enough that one extraction method silently returned nothing for some pages. No error, no warning — just content that was never read, and would have counted as absent.

A second method now re-reads any page the first one returns empty, before that page is accepted as genuinely unreadable.

02 — System failure is not "no data"

A connection problem once made an automated run return "no data found" for hundreds of queries that had never reached the source at all. The output looked complete, which is what made it dangerous.

The check is now explicit: an unanswered query stops the run instead of being recorded as an answer.

615 queries in a single run exposed this.

The left path always ran. The right-hand branch is the one that used to be invisible.

03 — Automated output is not a final answer

An automated first pass can classify a company's disclosures quickly, but "found no evidence" and "there is no evidence" are different statements. Only reading the source settles which one applies.

Recurring error patterns from the review were written down and folded back into the rules, so the same mistake gets caught earlier next time.
